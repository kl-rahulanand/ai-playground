evidence, reversible actions, and uncertainty.

Return only one valid JSON object. Do not use Markdown or place the JSON inside

Example 1 — deployment and competing infrastructure explanation:

Incident:
An API error rate increased shortly after a deployment. Network packet loss was
also reported.

Correct reasoning:
Treat deployment regression and network degradation as competing hypotheses.
Temporal proximity supports investigating the deployment, but does not prove
causation. Compare failures by version and examine request-level network data.

Example 2 — contradictory evidence:

Incident:
A deployment completed before an error increase, but old and new application
versions have equal failure rates. A downstream service reports a confirmed
outage.

Correct reasoning:
Equal failure rates weaken the deployment hypothesis. The confirmed downstream
outage is better supported, although request traces are still required before
claiming it caused every failure.

Example 3 — no recent deployment:

Incident:
Checkout failures increased without a recent deployment. Database connections
were saturated and an external provider reported errors.

Correct reasoning:
Consider database degradation and provider failure. Do not introduce a
deployment regression because no deployment was reported. Determine whether
failed requests contain database errors, provider errors, or both.

Rules:

1. Preserve the supplied facts.
2. Separate observations from interpretations.
3. Do not invent logs, metrics, events, configuration changes, or system behaviour.
4. Do not claim a confirmed root cause unless the evidence establishes it.
5. Do not treat a previous similar incident as proof of the same cause.
6. Do not treat alert time as the exact incident-start time.
7. A rollback result may strengthen or weaken a hypothesis without necessarily proving it.

Incident:

INC-104 — Checkout failures after a deployment

At 10:04 UTC, the checkout error-rate alert fired after failures increased from
0.4% to 9%.

Deployment dep-1842 for checkout-api completed at 10:01 UTC.

Database latency increased at approximately the same time.

The external payment provider reported intermittent errors.

A previous incident with similar symptoms involved an expired service credential.

The incident director asks:

What is the likely cause, and should we roll back?

Known limitation: this incident brief contains initial reports, not a confirmed
timeline or root cause.
